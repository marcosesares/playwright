## Module 1: playwright-core/client

**Path:** `packages/playwright-core/src/client/`
**Purpose:** Public user-facing API. All classes users interact with directly.

### Architecture

The entire client layer is built on `ChannelOwner<T extends channels.Channel>` — an abstract base class that wraps a Proxy object as its `_channel`. Every method call on that proxy goes through:

1. Parameter validation (via `maybeFindValidator`)
2. `_wrapApiCall` — captures stack trace, creates `ApiZone`, calls instrumentation hooks
3. `connection.sendMessageToServer` — dispatches JSON RPC to server

## Module 2: playwright-core/server

**Path:** `packages/playwright-core/src/server/`
**Purpose:** Browser control implementation — spawns browsers, executes commands, manages lifecycle.

### Architecture

Server-side objects extend `SdkObject` which extends `EventEmitter`. The `SdkObject` carries:
- `guid` — unique string ID (format: `prefix@uuid`)
- `attribution` — chain of parent objects (`playwright → browserType → browser → context → page → frame`)
- `instrumentation` — shared `Instrumentation` instance for hooks/logging

🟢 CONFIRMADO — `instrumentation.ts:49-60`

### Attribution Chain

```
SdkObject (Playwright root)
  └── BrowserType (chromium / firefox / webkit)
        └── Browser
              └── BrowserContext
                    └── Page
                          └── Frame (main + iframes)
                          └── Worker
```

## Module 3: playwright-core/server/dispatchers

**Path:** `packages/playwright-core/src/server/dispatchers/`
**Purpose:** RPC bridge layer — wraps server SdkObjects and exposes them over the wire protocol to clients.

### Architecture

`Dispatcher<Type, ChannelType, ParentScopeType>` mirrors `ChannelOwner` on the server side:
- Each `SdkObject` gets exactly one `Dispatcher` wrapper
- Registered in `DispatcherConnection` by guid
- Receives protocol messages from client → calls server methods
- Emits protocol events to client when server objects fire events

🟢 CONFIRMADO — `dispatcher.ts:52-80`

### Key Types

| Type | Purpose |
|------|---------|
| `Dispatcher<Type, Channel, Parent>` | Base RPC object |
| `DispatcherScope` | Scope that owns child dispatchers |
| `DispatcherConnection` | Owns all dispatchers, routes messages |

### GC Bucket System

🟢 `dispatcher.ts:41-51`

Each dispatcher has a `_gcBucket` string (defaults to type name). Max live dispatchers per bucket:
- `JSHandle`: 100,000
- `ElementHandle`: 100,000
- All others: 10,000

When limit exceeded → oldest dispatchers GC'd and clients notified.

## Module 4: playwright-core/tools/mcp

**Purpose:** MCP (Model Context Protocol) server — exposes browser automation as AI-callable tools.

### Architecture

### BrowserModel (Extension Relay)

🟢 `browserModel.ts:50-80`

Manages Chrome extension ↔ Playwright CDP bridge:
- `_knownTabs: Map<number, Tab>` — tabs observed but not yet attached
- `_tabSessions: Map<number, TabSession>` — attached tabs with assigned session IDs

- 🟢 headless defaults to `true` if `os.platform() === 'linux' && !process.env.DISPLAY`
- 🟢 `--disable-blink-features=AutomationControlled` injected for Chromium by default
- 🟢 `initPage`/`initScript` paths resolved against config-file dir, not cwd
