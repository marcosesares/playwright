## High-Risk Change Areas

### 1. Protocol YAML (`packages/protocol/spec/*.yml`)
🟢 CONFIRMADO

**Impact radius: FULL** — any change cascades to all 4 layers simultaneously.

**Required steps for ANY protocol change:**
1. Edit YAML spec file(s)
2. Regenerate `channels.d.ts` + validators (`npm run watch` / `generate_channels`)
3. Update client-side `ChannelOwner` subclass + method
4. Update `Dispatcher` subclass + handler
5. Update server-side `SdkObject` implementation
6. Write / update tests

**Risk:** Protocol changes are the highest-friction changes in the codebase. A missed step breaks either type safety (caught by `flint`) or runtime behavior (caught by tests).

---

### 2. ChannelOwner Base Class (`channelOwner.ts`)
🟢 CONFIRMADO

**Impact radius: ALL CLIENT OBJECTS**

Every public API object extends `ChannelOwner`. Changes to:
- `_wrapApiCall` → affects all tracing, error stacks, ApiZone capture
- `_createChannel` → affects all RPC serialization
- `_updateSubscription` → affects all event subscription protocol traffic
- `_dispose` → affects all object lifecycle

**Risk:** A regression here impacts 100% of user-facing API calls.

---

### 3. SdkObject / Attribution / Instrumentation (`instrumentation.ts`)
🟢 CONFIRMADO

**Impact radius: ALL SERVER OBJECTS**

All server objects extend `SdkObject`. Changes to attribution chain affect:
- Tracing (CallMetadata captures attribution)
- Test runner hooks (onBeforeCall, onAfterCall use attribution)
- Error reporting (attribution chain shown in error messages)

**Risk:** High — changes often require updating all browser-specific implementations (chromium/, firefox/, webkit/).

---

### 4. Dispatcher Base (`dispatcher.ts`) + GC Bucket System
🟢 CONFIRMADO

**Impact radius: ALL DISPATCHERS**

The GC bucket limits (10k general, 100k handles) affect memory usage at scale. A change to eviction logic impacts all handle-heavy scenarios.

**Risk:** Medium — GC bugs manifest intermittently under load, hard to reproduce.

---

### 5. Injected Scripts (`packages/injected/src/`)
🟡 INFERIDO

**Impact radius: Selector behavior, Recorder, ARIA assertions, Clock**

- `selectorGenerator` changes affect Recorder output quality
- `ariaSnapshot` changes affect `toMatchAriaSnapshot()` assertions across all tests
- `selectorEngine` changes affect how Locator resolves elements in ALL interactions

**Risk:** High for user-facing selector stability. Hard to test in isolation (requires live browser).

## DEPS Boundary Impact

🟢 CONFIRMADO — `DEPS.list` files (52+ across repo) enforce import boundaries.

| Boundary | Rule | Risk if violated |
|----------|------|-----------------|
| client → server | PROHIBITED | Type safety lost; server internals exposed to users |
| server → client | PROHIBITED | Circular dependency; server would depend on user-facing API |
| injected → Node.js | PROHIBITED | Injected scripts run in browser context — no Node.js APIs |
| isomorphic | Must be safe for both Node.js and browser | Breaking change affects both client and injected |

**Detection:** `npm run flint` runs `check-deps` which validates all `DEPS.list` files. Any violation fails CI.
