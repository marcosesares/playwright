## Overview

🟡 INFERIDO — Playwright is a developer tool, not a multi-user application. There is no traditional RBAC or user authentication system in the core library or test runner.

The closest analog to a permissions system is the **MCP Tool Capability** model, which controls which groups of browser automation tools are exposed when Playwright runs as an AI agent backend.

---

## MCP Tool Capability Matrix

🟢 CONFIRMADO — `packages/playwright-core/src/tools/mcp/config.d.ts:21-27`, `program.ts:41`

The `--caps` flag (or `PLAYWRIGHT_MCP_CAPS` env var) selects which tool groups are enabled. Unlisted capabilities are disabled.

| Capability | CLI Flag / Name | Description |
|-----------|-----------------|-------------|
| `config` | `config` | Configuration management tools |
| `core` | `core` | Core browser automation (navigate, click, fill, screenshot) |
| `core-navigation` | `core-navigation` | Navigation-specific core tools |
| `core-tabs` | `core-tabs` | Tab management tools |
| `core-input` | `core-input` | Input interaction tools |
| `core-install` | `core-install` | Browser install tools |
| `network` | `network` | Network interception and inspection |
| `pdf` | `pdf` | PDF generation |
| `storage` | `storage` | Cookie/storage access |
| `testing` | `testing` | Test assertion tools |
| `vision` | `vision` | Screenshot-based visual tools (legacy: `--vision`) |
| `devtools` | `devtools` | Chrome DevTools Protocol access |

**Notes:**
- `--vision` (deprecated) is an alias for `--caps=vision`. Emits a deprecation warning.
- `--caps=tracing` implicitly adds `devtools` capability.

## Network Access Controls (MCP)

🟢 CONFIRMADO — `packages/playwright-core/src/tools/mcp/config.ts`

| Option | Purpose |
|--------|---------|
| `allowedHosts` | Allowlist of hostnames the browser may connect to |
| `allowedOrigins` | Allowlist of origins for browser requests |
| `blockedOrigins` | Blocklist of origins |
| `blockServiceWorkers` | Prevents service worker registration |
| `allowUnrestrictedFileAccess` | Allows file:// access beyond current dir |

These act as runtime access controls on network-level operations. No authentication — purely origin/host filtering.

## File System Access Controls (MCP)

🟢 CONFIRMADO — `packages/playwright-core/src/tools/backend/context.ts:386`

| Rule | Enforcement |
|------|------------|
| Output directory cannot be a system directory | `isSystemDirectory()` check at startup |
| Working directory must be writable | `isWritable()` check at startup |
| `localPaths` for file uploads rejected when client ≠ server host | Runtime rejection with clear error |

## Browser Sandbox Controls

🟢 CONFIRMADO — `packages/playwright-core/src/tools/mcp/config.ts`

| Option | Effect |
|--------|--------|
| `--sandbox` | Forces Chromium sandbox on |
| `--no-sandbox` | Forces Chromium sandbox off |
| *(default)* | Platform OS default |

Sandbox is a security boundary for the browser process, not for the Playwright user.

## Summary

This system has no user authentication, no roles, and no row-level access control. Permission control is entirely at the tool-capability and network-origin level, designed for AI agent safety (restrict what the AI can do) rather than multi-user data isolation.
